# Task 5: security checklist

Date: 2026-11-09. Ten items after one loophole fix, seven current defaults verified by web search (pnpm 11 `minimumReleaseAge` default, Astro `security.csp` stable since 6, npm `min-release-age`).

## asensio.me, `sec`, first run (nine items)

Structure passes: SEC-1 (high) three pnpm advisories from `pnpm audit` with GHSA ids, SEC-2 (medium) no CSP with the GitHub Pages header limitation stated, SEC-3 (medium) `withastro/action@v6` by tag. Loophole: the report wrote "The README claims no third-party requests; the code agrees", while `src/lib/gif.ts:1` builds `https://media.giphy.com/media/...` URLs and `src/pages/index.astro:715` fetches them. The orient rule in `SKILL.md` makes a contradiction a finding, but no item told the agent to enumerate origins, so it never looked.

Fix: item 9 "Third-party origins" added to `areas/security.md`: list every origin the shipped page contacts; finding when a document claims none exist, or a third-party script or stylesheet lacks Subresource Integrity.

## asensio.me, `sec`, rerun (ten items)

Pass. SEC-3 (medium, S): "README.md:5 says 'no third-party requests'; src/lib/gif.ts:1 builds `https://media.giphy.com/media/${id}` URLs ... the page script fetches the same origin at src/pages/index.astro:715-716". Origins listed: `media.giphy.com` only, with the dev-only Giphy search correctly excluded. SEC-2's CSP suggestion now includes `img-src 'self' https://media.giphy.com`. The user's secret-read guard blocked a read of the npm user config file; the agent fell back to `git ls-files`, which is the right behaviour.

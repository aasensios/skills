## asensio.me, run 1

- **Stack detected before listing?** In prose, one line: "Read-only review of asensio.me (Astro 7 static site, Vite+ toolchain, deployed to GitHub Pages)." Not a check the reader can correct; findings follow immediately.

## Failures to address

1. **No verdicts.** All four runs return flat lists. Nothing says whether an area is fine. Needs the binary verdict rule and the "Checked" list that makes a `Good` credible.
2. **No cap, no ranking.** 55 to 70 items per run. Rankings appear only as an ad hoc closing list in two of four runs. Needs the five-per-area cap and the impact-then-effort order.
3. **Evidence missing.** About a third of items cite a location. "Check", "verify" and "likely" items are presented as findings. Needs the rule that a finding without an evidence line is dropped, and that unchecked items go under "Not checked".
4. **Available commands not run.** No run used `npm outdated` or `npm audit` on gmail-clone, so vulnerability and outdated claims stayed guesses. Needs tier 2.
5. **Commands run outside the target.** Both asensio.me runs reported the skills repo's untracked `tests/` folder. Needs an explicit "every command runs with the audited root as its working directory" rule.
6. **Documented choices contradicted.** Three of four runs proposed leaving GitHub Pages, which the README documents. Needs the orient step and the "Skipped as documented choices" line. The Giphy versus "no third-party requests" catch shows why `security` and factual contradictions must not be suppressed.
7. **Menus instead of one suggestion.** "Playwright or Cypress", "Jest or Vitest". Needs one named default per need from a verified table.
8. **Tool currency hedged.** "current is 19 or later". Needs the current-defaults table with a verified date.
9. **Format drifts between runs.** Heading style, section order, closing lists and invented extra areas all differ. Needs the report template and the fixed area set.
10. **Stack detection is prose.** It is stated once and never printed as something to correct before findings. Needs the detection table as step 2's visible output.
